Setup instructions and database rules
PATHIRANA AUTO — GITHUB + FIREBASE

WHAT TO COPY
Only index.html is needed on your website. It includes all HTML, CSS and JavaScript.
Open it as text, select everything, and paste into a GitHub file named index.html.
Paste firestore.rules into Firebase's Rules editor, NOT into index.html.
No Python, terminal commands, packages, or build step are needed to run this app.

1. CREATE FIREBASE
Go to https://console.firebase.google.com and create a project.
Register a Web app using the </> icon in Project settings > Your apps.
Copy its firebaseConfig object. In index.html, find:
    const firebaseConfig = {
Replace that whole example object with your project's web configuration.
Use the public WEB APP configuration only. Never paste a service-account private key.

2. ENABLE SIGN-IN
In Firebase Authentication, enable Email/Password under Sign-in method.
In Authentication > Users, add your own email and a strong password.
Copy that user's UID. Create separate accounts for each staff member.
The website does not offer public sign-up.
In Authentication > Settings > Authorized domains, add your GitHub Pages domain,
for example YOURUSERNAME.github.io (no https:// and no repository path).
If using another host, add its domain instead.

3. CREATE AND LOCK THE DATABASE
Open Firestore Database, create the default database in Standard edition,
and choose production mode. Choose a suitable region during creation.
Open the Rules tab. Replace its contents with firestore.rules.
Replace REPLACE_WITH_OWNER_UID with your UID from Authentication > Users.
For more staff, add their UIDs as quoted strings separated by commas.
Publish the rules. All approved accounts can read and modify this workshop.
An unapproved or signed-out account cannot access these records under these rules.
Do not use test-mode or unrestricted allow read, write rules.
Each data change uses a transaction and advances a shared revision number.
Conflicting changes are rejected and refreshed, so the user can review and retry.

4. PUT THE WEBSITE ON GITHUB
Create a repository (or use your intended existing one).
Choose Add file > Create new file. Name it index.html.
Paste the entire index.html contents, including your Firebase configuration.
Choose Commit changes.
Under Settings > Pages, select Deploy from a branch, main, and / (root), then Save.
Open the website address GitHub supplies when deployment completes.
For GitHub Free, Pages requires a public repository. The website code is public;
customer records are stored separately in the access-controlled Firebase database.
Never upload customer exports, passwords, or service-account keys to GitHub.
GitHub Pages is optional: this same index.html can be served by another static host.

5. SIGN IN AND TEST
Use the account created in Firebase Authentication.
Create a TEST customer, add a motorcycle, add a part with quantity 1,
create a job, and assign the part. Stock should become 0.
Set labour, issue the invoice, record payment, and print if needed.
Open the site on a second device with an approved account and verify the records.
Test a signed-out/unapproved account with Firebase's Rules simulator as well.
Only begin entering real customer data after these checks succeed.

INCLUDED
Dashboard; customer and motorcycle records; searchable job history; job status;
work notes and labour; spare parts; restocking and low-stock alerts; parts use
and returns; invoices; cash/card/bank-transfer payment records; job sorting and service classification; income/expense tracking; native share/copy summaries; print; JSON export.
Recording a card payment does not process a card or connect to a bank.
Invoices and finance summaries are workshop management records, not a configured tax/accounting system.

LIMITS AND BACKUP
Internet is required. No offline data entry is supported.
The app reads the workshop's records into memory, so it is a small-workshop starter;
it will need pagination and more selective queries for a large historical database.
All approved staff have the same access level. There is no administrator dashboard,
record deletion screen, customer editing, automatic backup, or restore UI yet.
Backup downloads JSON for safekeeping. It is an export, not automatic disaster recovery.
Keep exports somewhere private. Do not upload them into the public repository.
Your earlier browser-only records are not automatically imported or overwritten.
Firebase quotas and pricing apply; check Usage in your console.
The website is not connected to your Firebase project until you complete setup.
Cloud login, real-device syncing and the rules must be verified in your project.
